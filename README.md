# ValutaTrade Hub

Консольное приложение для работы с виртуальным валютным портфелем. Можно зарегистрироваться, покупать и продавать валюту, смотреть остатки в кошельках и получать курсы из внешних API.

Поддерживаются USD, EUR, GBP, RUB, BTC, ETH и SOL. Настоящие деньги и реальные сделки приложение не использует.

## Установка и запуск

Нужны Python 3.12 или новее и uv.

Скачайте проект и установите зависимости:

```bash
git clone https://github.com/AntonSamsonovY/finalproject_samsonov_m26-555.git
cd finalproject_samsonov_m26-555
uv sync
```

Запустите приложение:

```bash
uv run valutatrade-hub
```

Команды ниже вводятся внутри приложения. Для выхода используйте `exit`.

Запускайте приложение из корня проекта, чтобы оно использовало настройки из `pyproject.toml`.

## Настройка источников курсов

Для обычных валют используется ExchangeRate-API, для криптовалют - CoinGecko.

Ключ ExchangeRate-API передаётся через переменную окружения. В терминале перед запуском приложения выполните:

```bash
export EXCHANGERATE_API_KEY="ваш_ключ"
```

Если используется Demo API-ключ CoinGecko:

```bash
export COINGECKO_DEMO_API_KEY="ваш_ключ"
```

Без ключа CoinGecko приложение тоже отправляет запрос, но доступность зависит от ограничений сервиса. Если запрос отклонён, можно указать Demo API-ключ.

Названия переменных есть в `.env.example`. Сам файл `.env` автоматически не загружается: переменные нужно передать в окружение процесса.

Ключи не следует добавлять в код, коммиты или запись демонстрации.

## Пример работы

Зарегистрируйтесь и войдите:

```text
register --username anton
login --username anton
```

После каждой команды приложение отдельно запросит пароль. При регистрации нужен пароль длиной не менее четырёх символов. При вводе он не отображается.

Обновите курсы и добавьте валюту в портфель:

```text
update-rates
buy --currency BTC --amount 0.01
buy --currency EUR --amount 100
show-portfolio
```

Посмотрите стоимость портфеля в другой валюте и продайте часть BTC:

```text
show-portfolio --base EUR
get-rate --from BTC --to USD
sell --currency BTC --amount 0.005
show-portfolio
```

В `--amount` указывается количество выбранной валюты, а не сумма в долларах.

В этом проекте `buy` увеличивает баланс выбранного кошелька, а `sell` уменьшает его. Отдельного списания или начисления USD нет. Курс используется для расчёта оценочной стоимости операции и портфеля.

Новый пользователь получает пустой портфель. Кошелёк создаётся при первой покупке. Продать больше, чем есть на балансе, нельзя.

## Команды

```text
register --username <имя>
login --username <имя>

buy --currency <код> --amount <количество>
sell --currency <код> --amount <количество>

show-portfolio [--base <код>]
get-rate --from <код> --to <код>

update-rates [--source coingecko|exchangerate]
show-rates [--currency <код>] [--top <N>] [--base <код>]

whoami
logout
help
exit
```

Для `register` и `login` доступен аргумент `--password`, но отдельный ввод удобнее: пароль не остаётся в строке команды.

Примеры просмотра курсов:

```text
update-rates --source coingecko
show-rates
show-rates --currency BTC
show-rates --top 2
show-rates --currency BTC --base EUR
```

`--top` выбирает самые дорогие криптовалюты среди отслеживаемых приложением, а не среди всего рынка. Цена сравнивается за одну единицу валюты.

Для регистрации, входа и работы с портфелем используются локальные данные. Получение и просмотр курсов не требуют входа в аккаунт.

## Кэш и история курсов

Курсы сохраняются в `data/rates.json`. По умолчанию срок актуальности кэша - 300 секунд с момента получения ответа.

Если нужный курс отсутствует или устарел, приложение пробует обновить его. Если обновление не удалось, операция с валютой не сохраняется.

Команда `show-rates` не обращается к API. Она показывает сохранённые данные и отдельно помечает устаревшие курсы.

Все полученные пары приводятся к направлению валюты к USD. Обратные и кросс-курсы рассчитываются из этих значений. Например:

```text
BTC → EUR = BTC → USD / EUR → USD
```

Время получения ответа и время обновления курса у самого источника хранятся отдельно. Поэтому актуальность кэша не означает, что источник пересчитывает рыночный курс каждые пять минут.

История измерений находится в `data/exchange_rates.json`. Повторное сохранение одного измерения не создаёт дубликат. Более старый ответ не заменяет новый курс.

Если один источник недоступен, данные другого всё равно сохраняются. Приложение сообщает, какая часть обновления не удалась.

## Данные и журнал

Рабочие файлы создаются автоматически:

```text
data/
├── users.json
├── portfolios.json
├── rates.json
└── exchange_rates.json

logs/
└── valutatrade.log
```

Пароли сохраняются в виде SHA-256-хеша с индивидуальной солью. Это учебная схема из задания, а не готовое решение для хранения паролей в реальном сервисе.

JSON сохраняется через временный файл и замену целевого. Для незавершённого сохранения предусмотрен служебный снимок: запись завершается при следующем обращении к соответствующему хранилищу. Повреждённые файлы не перезаписываются автоматически.

В журнал попадают покупки, продажи, ошибки и этапы обновления курсов. Для записи баланса до и после успешной операции добавьте `--verbose`:

```text
buy --currency BTC --amount 0.01 --verbose
```

При достижении заданного размера журнал переносится в архивный файл. Рабочие данные, журналы и файлы с ключами исключены из Git.

Приложение рассчитано на запуск одного экземпляра с общей папкой данных.

## Настройки

Основные параметры находятся в `pyproject.toml`:

```toml
[tool.valutatrade]
data_dir = "data"
logs_dir = "logs"
rates_ttl_seconds = 300
default_base_currency = "USD"
log_format = "text"
log_level = "INFO"
log_max_bytes = 1048576
log_backup_count = 3
```

Для журнала доступны форматы `text` и `json`. Для отладки можно установить уровень `DEBUG`.

Пути также можно передать через переменные окружения:

```bash
export VALUTATRADE_DATA_DIR="/путь/к/данным"
export VALUTATRADE_LOGS_DIR="/путь/к/журналам"
```

Адреса API, списки запрашиваемых валют и таймаут находятся в `valutatrade_hub/parser_service/config.py`. По умолчанию таймаут запроса - 10 секунд.

## Структура проекта

```text
valutatrade_hub/
├── cli/              # команды и вывод в терминале
├── core/             # пользователи, кошельки и операции
├── infra/            # настройки и JSON-хранилище
├── parser_service/   # API-клиенты, обновление и история курсов
├── decorators.py     # журналирование операций
└── logging_config.py # формат журнала и ротация

tests/                # автоматические проверки
```

`SettingsLoader` создаёт один экземпляр настроек через `__new__`. Остальные сервисы получают зависимости при создании, поэтому их можно проверять отдельно от консоли и сети.

## Проверки и сборка

Запуск тестов:

```bash
uv run pytest
```

Проверка кода и форматирования:

```bash
uv run ruff check .
uv run ruff format --check .
```

Сборка пакета:

```bash
uv build
```

Wheel и исходный архив появятся в папке `dist/`.

Те же действия доступны через Makefile:

```bash
make install
make run
make test
make lint
make build
```

Тесты проверяют модели, регистрацию и вход, операции с кошельками, команды, кэш, историю, ошибки API и журналирование. Ответы API в тестах подменяются, поэтому для их запуска не нужны сеть и настоящие ключи.
